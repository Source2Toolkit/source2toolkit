KHook: SourceHook is gone, one hook engine for the whole server.
KHook version handshake: the core reports the commit it was built against, plugins refuse to load on a mismatch.
KHOOK_* hook macros in the SDK; IToolkitGameConfig::ResolveSignature hands back an IToolkitMemory (IToolkitGameConfig002); IToolkitMemory::GetPtr is a void*, GetAddr the integer.
Fix: UnloadAll closes plugin libraries only after every plugin's registrations are gone (SIGSEGV on shutdown when a command wrapped another plugin's handler).
IToolkitModule::GetVirtualTableByOffset / GetVirtualTableByBase: secondary vtables, for an interface that is not a class's first base (KHOOK_VTABLE_BASE in the SDK). DynLibUtils bumped, FindPattern out-of-bounds fixes included.
IToolkitSounds: sound events sent by the core -- per-player recipients, instant stop by guid, per-player volume channels, HOOK_SOUND on the game's own sounds. Fixes: net-message hook handles are the protobuf (GetInt32 & co. crashed in a server-message hook), FireEvent before LoadEventsFromFile no longer crashes. IToolkitAPI gained Sounds(): rebuild plugins against the new SDK.
Fix: a plugin that refuses to load is logged with its reason and no longer crashes "toolkit list" (it stayed in the plugin list after its library was closed); LoadAll() reports how many did not load. IToolkitSound::New() + plain delete. Built against KHook 40d233d, the SDK pin follows.
IToolkitTransmit: per-viewer entity visibility (hook an entity, show or hide it per viewer on eight channels, BlockAll, owner-following, a player hidden through the controller), plus HookCheckTransmit with a wrapped transmit set per viewer whose BlockTransmit sets the non-players bit too, so hidden entities come back without the "missing client entity" client crash. GameFrame no longer pushes player names and scores to Steam every frame. IToolkitAPI gained Transmit(): rebuild plugins against the new SDK, which also brings tools/deps.py (init/update of hl2sdk-cs2, Protobufs, KHook pin and manifests).
Retry of the IToolkitTransmit release: the Windows build tripped over the min() macro in transmit.cpp.
2026-09-23 engine sync: gamedata for Linux and Windows (16 + 24 signatures, CBaseEntity/CCSPlayerController/CCSGameRules vtable offsets, CNetworkGameServer::ClientList 616) and the SDK schema regenerated from a fresh dump (removed classes and fields no longer compile).
Rebuild of the 2026-09-23 engine sync against the hl2sdk update that landed after v1.0.17 (EntityIOQueuePrioritizedEvent_t, IFileSystem::String and the three removed IFileSystem slots, GetScriptDesc).
Rebuild against the hl2sdk that follows the 2026-09-23 update in full: CEntityInstance vtable (Pulse_OnDynamicAttributeChanged at 43, so GetDataDescMap and later virtuals moved), INetworkGameServer::GetServerState, datamap_t/typedescription_t, CEntityClass, variant fieldtype_t.
Windows package ships source2toolkit.dll again (it was built into the build root and left out of every Windows tarball since at least v1.0.16); built against hl2sdk with the ScriptClassDesc_t fix (#428).
Schema: NetworkStateChanged of embedded objects (CEconItemView, CCollisionProperty, ...) is found at runtime through the new gamedata signature NetworkVar::StateChanged instead of vtable slot 1 (CEconItemView writes never replicated); GetManipulator works for every collection field (per-player custom HUD state); networked flags are resolved once the entity system exists; the schema API takes a class type or pointer and finds inherited fields.
CI stays on the official alliedmodders metamod-source/hl2sdk but now fails on a KHook drift between metamod-source third_party/khook and source2toolkit-sdk vendor/khook (both 2a89535) instead of shipping a core that refuses every plugin.
Addresses: every function signature in gamedata is resolved (RESOLVE_SIG takes only the entry name; module from its "library"), mandatory for what the toolkit or an SDK helper calls, optional for plugin-only hook targets; new PostThink, UTIL_Remove, DispatchParticleEffect, GetWeaponCSDataFromKey, GetNavMeshData, LogDirect, Cmd_ExecuteCommand and the real GiveNamedItem. Gamedata and prototypes checked against the Linux and Windows binaries: GetViewVectors 32/33, TakeDamageOld, CCSGameRules::TerminateRound, CCSPlayerPawnBase::CanMove, jump handlers on CCSPlayerLegacyJump/ModernJump, AcceptInput returns bool. SDK helpers take HookChain::Run/Bypass; the core fills the SDK globals itself. License: MIT exception for plugins (closed-source or commercial allowed).
IToolkitScripts: plugins run cs_script -- compiled .vjs assets, raw source and hot-reloaded .js files in point_script entities, RunScriptInput into a script and `toolkit_script <channel> <payload>` messages back (server only); persistent scripts survive round restarts and map changes. Command listeners: Override no longer stops the chain. Superseded game events are freed. ConVar lookups return TOOLKIT_INVALID_CONVAR_INDEX (0 is a real ConVar). Malformed gamedata no longer throws at startup. `late` is true for every load after startup. MySQL connection queries always answered and read on the worker; menu fixes (page keys, use-after-free on submenu, reshaped menus).
Unloading from the console no longer deadlocks: "meta unload" of the toolkit and "toolkit unload" of a plugin used to wait, from inside the ICvar::DispatchConCommand call the command arrived through, for that same call to return, and the watchdog killed the server. Virtual hooks are now abandoned at unload (SDK IToolkitKHook.h, KHOOK_DESTRUCT does it) and removed afterwards -- by metamod's unloader for the toolkit, by the core on a thread of its own for a plugin, whose library is closed only once KHook is done with it. Shutdown SIGSEGV in tier0 fixed: hl2sdk's ConVar_Unregister now walks the registration list, so the toolkit's own ConCommands are created after ConVar_Register instead of being deleted out from under it. Breaking, rebuild plugins against the SDK: IToolkitListener::OnPluginLoad/OnPluginUnload take the plugin's name as a second argument. vprof: every core hook handler is a scope under one "Source2Toolkit" budget group.
Plugin API 2. IToolkitGameHooks: the game functions plugins hook most (TakeDamage, CanAcquire, CanMove, CanUse, PostThink, ProcessUsercmds, RunCommand, AcceptInput, Touch, DropWeapon, the movement services and the jump components) are hooked once by the core from its gamedata, on the first listener and only while one is registered; a handler gets a context and returns an Action, and a changed prototype or platform argument order is the core's to fix. IToolkitListener engine callbacks (OnGameFrame, OnStartupServer, OnClientPutInServer/Voice/SettingsChanged/Disconnect, the Steam API pair, OnLoadEventsFromFile) replace the KHOOK_VIRTUALs every plugin carried. KHOOK_GAMEDATA(&Class::Method, "name") checks a virtual hook's slot against gamedata, which wins; the core's own hooks do the same (linux offsets in gamedata, Windows falls back to the header). A schema field missing from the running game now does nothing instead of writing at offset 0. Unloading the toolkit from the console ("meta unload") no longer deadlocks: the command is superseded and re-issued from the next game frame once the DispatchConCommand hook is gone, and every hook is deleted synchronously as before -- the v1.0.25 "abandon" mechanism is reverted. "toolkit unload" is deferred to the next frame the same way. A plugin built against API 1 still loads.
Interface revisions: the factory serves the current revision of each interface, an older one through a compat adapter (none needed yet) with a warning, and refuses a newer one with "update the core"; "toolkit list" shows each plugin's API, KHook commit and tier (stable: no raw KHook hooks of its own, so a KHook or engine change needs only a core update; raw: rebuild), "toolkit info" adds the interfaces it uses. The KHook commit check moved from TOOLKIT_SAVEVARS into KHOOK_INIT(), so a plugin without raw hooks never fails it. Command handlers receive ToolkitCommandContext/ToolkitCommandArgs instead of the engine's CCommandContext/CCommand (SDK change, rebuild plugins). Plugin unload and hot reload run from the server command buffer between frames instead of inside GameFrame: a plugin hooking GameFrame deadlocked the server on hot reload.
IToolkitGameHooks002: HookX() returns a GameHookId and each function has its own UnhookX(id), so a plugin with several handlers on one function can drop one of them; the enum-based Unhook and UnhookAll are gone (the core still drops a plugin's handlers at unload).
